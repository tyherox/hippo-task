## 1. Design Principles

1. **Universal 80%** — Core fields capture what every major platform has in common.
2. **Lossless overflow** — Platform-specific data that doesn't map to core fields flows into `metadata` without data loss.
3. **Raw + normalized** — Certain fields (status, priority) have both a normalized HippoTask value and a `*_raw` string preserving the original platform value.
4. **Optional by default** — Only `id`, `title`, `status`, `created_at`, `updated_at`, and `schema_version` are required. Everything else is optional. This keeps the schema usable for quick AI agent tasks as well as full platform syncs.
5. **Flat-ish structure** — Nesting is kept minimal. Relationships are expressed via IDs, not embedded objects.
6. **JSON-native** — The schema is defined for JSON. It can be serialized to YAML trivially, but JSON is the wire format.

## 2. Core Types

### HippoTask

The central type. Represents a single unit of work.

```typescript
interface HippoTask {
  // ─── Identity ───────────────────────────────────────────────
  /** Unique identifier. Generated by HippoTask (UUIDv7). */
  id: string;

  /**
   * Map of external platform IDs.
   * Keys are platform names, values are platform-specific IDs.
   * Example: { "jira": "PROJ-123", "linear": "LIN-abc-def" }
   */
  external_ids?: Record<string, string>;

  // ─── Content ────────────────────────────────────────────────
  /** Task title / summary. Required. */
  title: string;

  /**
   * Task description body.
   * Canonical format is Markdown. See Section 7 for format handling.
   */
  description?: string;

  /**
   * Hint about the description's format.
   * Defaults to "markdown" if omitted.
   */
  description_format?: DescriptionFormat;

  // ─── Workflow ───────────────────────────────────────────────
  /**
   * Normalized status. Required.
   * See HippoStatus enum for allowed values.
   */
  status: HippoStatus;

  /**
   * Original platform status string, preserved for lossless round-tripping.
   * Example: "In Code Review" (from Linear), "Waiting for QA" (from Jira)
   */
  status_raw?: string;

  /**
   * Normalized priority level.
   * If the source platform has no priority concept, this is omitted.
   */
  priority?: HippoPriority;

  /** Original platform priority string or number. */
  priority_raw?: string | number;

  // ─── People ─────────────────────────────────────────────────
  /**
   * Users assigned to this task.
   * Array to support platforms that allow multiple assignees (ClickUp, Trello, GitHub).
   * Single-assignee platforms populate a one-element array.
   */
  assignees?: HippoPerson[];

  /** The user who created this task. */
  creator?: HippoPerson;

  // ─── Time ───────────────────────────────────────────────────
  /** When the task was created. ISO 8601 datetime string. Required. */
  created_at: string;

  /** When the task was last updated. ISO 8601 datetime string. Required. */
  updated_at: string;

  /** When the task is due. ISO 8601 date or datetime string. */
  due_date?: string;

  /** When work on the task should start. ISO 8601 date or datetime string. */
  start_date?: string;

  /** When the task was completed/resolved. ISO 8601 datetime string. */
  completed_at?: string;

  // ─── Organization ───────────────────────────────────────────
  /**
   * The project/container this task belongs to.
   * References a HippoProject.id.
   */
  project_id?: string;

  /**
   * Parent task ID, for subtask relationships.
   * References another HippoTask.id.
   */
  parent_id?: string;

  /** Free-form labels/tags for categorization. */
  labels?: string[];

  // ─── Estimation ─────────────────────────────────────────────
  /**
   * Effort estimate as a numeric value.
   * The meaning depends on estimate_unit.
   */
  estimate?: number;

  /** Unit for the estimate value. Defaults to "points" if omitted. */
  estimate_unit?: EstimateUnit;

  // ─── Extension ──────────────────────────────────────────────
  /**
   * Typed custom fields.
   * For structured data that doesn't fit core fields but has a known type.
   * Keys are field names/slugs.
   */
  custom_fields?: Record<string, HippoCustomField>;

  /**
   * Untyped metadata overflow.
   * For adapter-specific data that doesn't fit core fields or custom_fields.
   * Preserved for lossless round-tripping.
   * Keys are namespaced: "jira.sprint_id", "linear.cycle_id", etc.
   */
  metadata?: Record<string, unknown>;

  // ─── Schema ─────────────────────────────────────────────────
  /** Schema version this task conforms to. Semver string. Required. */
  schema_version: string;
}
```

### Required vs. Optional Fields

| Field | Required | Rationale |
|-------|----------|-----------|
| `id` | ✅ | Every task must be identifiable |
| `title` | ✅ | Every task must have a name |
| `status` | ✅ | Workflow state is fundamental |
| `created_at` | ✅ | Audit trail |
| `updated_at` | ✅ | Sync conflict resolution |
| `schema_version` | ✅ | Forward compatibility |
| Everything else | ❌ | Keep the bar low for quick tasks, AI agents |

## 3. Enumerated Types

### HippoStatus

```typescript
type HippoStatus =
  | "backlog"      // Known but not ready to start
  | "todo"         // Ready to be worked on
  | "in_progress"  // Actively being worked on
  | "in_review"    // Work done, awaiting review/approval
  | "done"         // Completed successfully
  | "cancelled";   // Abandoned / won't do
```

**Design note:** This is intentionally a small set. Complex workflow states are preserved in `status_raw` and can be mapped via adapter configuration. The six statuses cover >95% of use cases across all surveyed platforms.

### HippoPriority

```typescript
type HippoPriority =
  | "none"    // No priority set
  | "low"     // Low importance
  | "medium"  // Normal importance
  | "high"    // High importance
  | "urgent"; // Critical / blocking
```

### DescriptionFormat

```typescript
type DescriptionFormat =
  | "markdown"   // Default. Canonical format.
  | "plaintext"  // No formatting.
  | "html";      // Rich HTML (from Asana, etc.)
```

**Note:** Platform-specific formats (ADF, Notion Blocks) are converted to Markdown by adapters before reaching the schema. The `description_format` field exists for cases where conversion is not desired or not possible.

### EstimateUnit

```typescript
type EstimateUnit =
  | "points"   // Story points / abstract units (default)
  | "hours"    // Time-based estimate
  | "minutes"; // Fine-grained time estimate
```

## 4. Supporting Types

### HippoPerson

Represents a user/person reference. Intentionally lightweight — HippoTask is not a user directory.

```typescript
interface HippoPerson {
  /** HippoTask internal ID (optional — may not exist if only syncing). */
  id?: string;

  /** Display name. */
  name?: string;

  /** Email address. Often the best cross-platform identifier. */
  email?: string;

  /**
   * External platform user IDs.
   * Example: { "jira": "5a09f....", "github": "octocat" }
   */
  external_ids?: Record<string, string>;
}
```

### HippoCustomField

Typed custom field for structured extension data.

```typescript
interface HippoCustomField {
  /** Human-readable field label. */
  label: string;

  /** Field data type. */
  type: CustomFieldType;

  /** The field value. Type depends on `type` field. */
  value: unknown;

  /**
   * For "select" and "multi_select" types: the allowed options.
   * Optional — may not be known outside the source platform.
   */
  options?: string[];
}

type CustomFieldType =
  | "string"
  | "number"
  | "boolean"
  | "date"       // ISO 8601 string
  | "select"     // Single choice from options
  | "multi_select" // Multiple choices from options
  | "url"
  | "email"
  | "person";    // References a HippoPerson
```

### TaskChangeEvent

Used by adapters to communicate task changes (for sync).

```typescript
interface TaskChangeEvent {
  /** The type of change. */
  type: "created" | "updated" | "deleted";

  /** The platform that originated this change. */
  platform: string;

  /** The external ID of the changed task. */
  external_id: string;

  /** The full task (for created/updated) or null (for deleted). */
  task?: HippoTask;

  /** ISO 8601 timestamp of when the change occurred. */
  timestamp: string;
}
```

### PaginatedResult

Standard pagination wrapper.

```typescript
interface PaginatedResult<T> {
  /** The items in this page. */
  items: T[];

  /** Total number of items (if known). */
  total?: number;

  /** Cursor for the next page (null if no more pages). */
  next_cursor?: string | null;

  /** Whether there are more pages. */
  has_more: boolean;
}
```

### TaskQuery

Query/filter parameters for listing tasks.

```typescript
interface TaskQuery {
  /** Filter by project. */
  project_id?: string;

  /** Filter by status(es). */
  status?: HippoStatus | HippoStatus[];

  /** Filter by assignee (email or HippoTask ID). */
  assignee?: string;

  /** Filter by label(s). */
  labels?: string[];

  /** Filter by priority. */
  priority?: HippoPriority;

  /** Tasks updated after this timestamp. */
  updated_since?: string;

  /** Free-text search in title and description. */
  search?: string;

  /** Maximum results to return. Default: 50, Max: 200. */
  limit?: number;

  /** Pagination cursor from a previous result. */
  cursor?: string;

  /** Sort field. Default: "updated_at". */
  sort_by?: "created_at" | "updated_at" | "due_date" | "priority" | "title";

  /** Sort direction. Default: "desc". */
  sort_direction?: "asc" | "desc";
}
```

## 5. Container Types

### HippoProject

Groups tasks together. Maps to Jira Project, Asana Project, Linear Project, ClickUp List, Trello Board, Monday Board, Notion Database, GitHub Repo/Project, Todoist Project, Planner Plan.

```typescript
interface HippoProject {
  /** Unique identifier. UUIDv7. */
  id: string;

  /** External platform IDs. */
  external_ids?: Record<string, string>;

  /** Project name. */
  name: string;

  /** Project description. Markdown. */
  description?: string;

  /** Project lifecycle status. */
  status?: ProjectStatus;

  /** ISO 8601 datetime. */
  created_at: string;
  updated_at: string;

  /** Untyped metadata overflow. */
  metadata?: Record<string, unknown>;

  schema_version: string;
}

type ProjectStatus =
  | "active"
  | "paused"
  | "completed"
  | "archived";
```

**Design note:** We intentionally do NOT model Workspace, Team, Space, Folder, Section, Board, List, Bucket, etc. as separate types. These are platform-specific organizational layers. HippoTask flattens everything to Project → Task (with optional subtasks via `parent_id`). Deeper hierarchy information is preserved in `metadata` for round-tripping.

## 6. Extension System

HippoTask provides three layers of extensibility, from most structured to least:

### Layer 1: `custom_fields` (Typed Extensions)

For data that has a known type and label but doesn't fit core fields:

```json
{
  "custom_fields": {
    "story_points": {
      "label": "Story Points",
      "type": "number",
      "value": 8
    },
    "environment": {
      "label": "Environment",
      "type": "select",
      "value": "production",
      "options": ["development", "staging", "production"]
    },
    "reviewed_by": {
      "label": "Reviewed By",
      "type": "person",
      "value": { "name": "Jane Smith", "email": "jane@example.com" }
    }
  }
}
```

**Use when:** The field has a clear name, type, and value. Custom fields from Jira, Asana, ClickUp, Notion, and Monday.com map here.

### Layer 2: `metadata` (Namespaced Overflow)

For platform-specific data that doesn't fit anywhere else:

```json
{
  "metadata": {
    "jira.sprint_id": "sprint-42",
    "jira.sprint_name": "Sprint 42",
    "jira.issue_type": "Story",
    "jira.resolution": "Fixed",
    "linear.cycle_id": "cycle-abc",
    "linear.team_key": "ENG",
    "clickup.space_id": "12345",
    "clickup.folder_id": "67890"
  }
}
```

**Convention:** Keys are namespaced with the platform name prefix (`platform.field_name`) to avoid collisions.

**Use when:** The data is platform-specific and needed for round-tripping, but doesn't have a universal meaning.

### Layer 3: `external_ids` (Cross-Reference)

For tracking which platform entities a HippoTask maps to:

```json
{
  "external_ids": {
    "jira": "PROJ-123",
    "linear": "ENG-456",
    "github": "owner/repo#78"
  }
}
```

**Use when:** A single HippoTask is synced to multiple platforms.

## 7. Description Format Handling

### Strategy

```
Platform A (ADF) ──→ Adapter A ──→ Markdown ──→ HippoTask
Platform B (HTML) ──→ Adapter B ──→ Markdown ──→ HippoTask
Platform C (MD)   ──→ Adapter C ──→ Markdown ──→ HippoTask (passthrough)
Platform D (Blocks)──→ Adapter D ──→ Markdown ──→ HippoTask

HippoTask ──→ Markdown ──→ Adapter A ──→ ADF ──→ Platform A
HippoTask ──→ Markdown ──→ Adapter B ──→ HTML ──→ Platform B
HippoTask ──→ Markdown ──→ Adapter C ──→ Markdown ──→ Platform C
HippoTask ──→ Markdown ──→ Adapter D ──→ Blocks ──→ Platform D
```

### Conversion Libraries (Recommended)

| Conversion | Library | Notes |
|-----------|---------|-------|
| Markdown → ADF | `md-to-adf` or custom | For Jira writes |
| ADF → Markdown | `adf-to-md` or custom | For Jira reads |
| Markdown → HTML | `marked` or `markdown-it` | For Asana writes |
| HTML → Markdown | `turndown` | For Asana reads |
| Markdown → Notion Blocks | `@tryfabric/martian` | For Notion writes |
| Notion Blocks → Markdown | `notion-to-md` | For Notion reads |

### Lossy Conversion Handling

Some conversions are inherently lossy (e.g., Markdown → plain text for MS Planner). When this happens:

1. The adapter performs the best-effort conversion.
2. The original Markdown is preserved in `metadata` as `hippotask.original_description_md`.
3. A `description_format` of `"plaintext"` indicates the loss occurred.

## 8. ID Strategy

### Internal IDs: UUIDv7

- **Format:** UUIDv7 (RFC 9562)
- **Rationale:** Time-sortable, globally unique, no coordination needed, 128-bit
- **Example:** `019470e1-3a4c-7f1c-8a5e-2b3c4d5e6f7a`

### External IDs: Platform-specific

Each platform uses its own ID format:

| Platform | ID Format | Example |
|----------|-----------|---------|
| Jira | Project key + number | `PROJ-123` |
| Asana | Numeric GID | `1234567890` |
| Linear | Team key + number | `ENG-456` |
| ClickUp | Alphanumeric | `abc123` |
| Trello | Alphanumeric hash | `5a0f3...` |
| Monday.com | Numeric | `123456789` |
| Notion | UUID | `a1b2c3d4-...` |
| GitHub | Owner/repo + number | `org/repo#42` |
| Todoist | Numeric | `1234567890` |
| MS Planner | Alphanumeric | `oISnkN...` |

External IDs are stored in the `external_ids` map and are never used as the HippoTask `id`.

## 9. Schema Versioning

### Strategy

- Version format: **Semver** (`major.minor.patch`)
- Every HippoTask object includes `schema_version`
- **Major bump:** Breaking changes to required fields or type changes
- **Minor bump:** New optional fields or new enum values
- **Patch bump:** Documentation, clarifications, no schema changes

### Migration Path

When a new schema version is released:
1. Old documents remain valid (new fields are optional).
2. A migration utility in `@hippotask/core` can upgrade old documents.
3. Adapters declare which schema versions they support.

### Current Version

`1.0.0-draft` — This document describes the initial draft. The version will become `1.0.0` when the schema is finalized and the first adapters are tested.

## 10. Validation Rules

Beyond type checking, the schema enforces these runtime validations:

| Rule | Field(s) | Description |
|------|----------|-------------|
| Non-empty title | `title` | Title must be a non-empty string after trimming |
| Valid status | `status` | Must be one of the `HippoStatus` enum values |
| Valid priority | `priority` | If present, must be one of the `HippoPriority` enum values |
| ISO 8601 dates | `created_at`, `updated_at`, `due_date`, `start_date`, `completed_at` | Must be valid ISO 8601 strings |
| Chronological dates | `start_date`, `due_date` | If both present, `start_date` ≤ `due_date` |
| Positive estimate | `estimate` | If present, must be > 0 |
| Valid schema version | `schema_version` | Must be a valid semver string |
| Unique external IDs | `external_ids` | Values must be non-empty strings |
| Custom field type match | `custom_fields[*].value` | Value must match declared `type` |

These validations will be implemented as Zod schemas in `@hippotask/core`, providing both compile-time TypeScript types and runtime validation.

## 11. JSON Schema Export

The Zod-defined schemas will be exported as standard JSON Schema (Draft 2020-12) via `zod-to-json-schema`. This allows:

- **Language-agnostic validation** — Python, Go, Ruby, etc. can validate HippoTask documents without TypeScript
- **Code generation** — Generate types in other languages from the JSON Schema
- **Documentation** — Auto-generate schema docs from the JSON Schema
- **OpenAPI integration** — Use the JSON Schema in API specs

The exported JSON Schema files will be published:
- In the `@hippotask/core` npm package under `/schema/`
- In the GitHub repository under `packages/core/schema/`
- On a documentation site (future)
